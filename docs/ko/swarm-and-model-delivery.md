# 지게차 스웜 조정과 연합 모델 전달

[← README](../../README.ko.md) · [English](../swarm-and-model-delivery.md) · [TR-0077 매핑](estimed-mapping.md) · [연합학습](federated-learning.md)

ESTIMED PoC는 둘을 이렇게 구분합니다.
- **스웜**은 현재 행동을 조정합니다. 범위가 정해진 컨텍스트를 공유하고, 조정 주기를 돌려 권고를 만들며, 참여자는 로컬 권한을 유지합니다.
- **연합학습**은 모델을 개선해 새 모델 버전을 만듭니다.

PoC는 "집계 ≠ 운영 모델 전달"이라고도 지적합니다. EdgeGuard는 둘 다 수행하고, 그 결과를 위험 엔진까지 연결합니다.

## 스웜 (TR-0077 7.4): [`edgeguard/swarm.py`](../../edgeguard/swarm.py)

```
sw_<forklift>            AE    멤버
  plan                   CNT   {"id", "prio" (1 = 적재), "route": [[교차로, 도착 s], ...]}
  advice                 CNT   채택한 출발 지연
<MEC AE>/swarm_<zone>    GRP   멤버 = 구역 내 지게차의 plan 컨테이너 (MEC 앱이 갱신)
```

- **멤버십:** 구역마다 `<group>` 하나. 지게차가 들어오고 나갈 때 추가·삭제됩니다.
- **컨텍스트:** 각 멤버가 **요청 한 번**(`GET <group>/fopt/la`)으로 모든 멤버의 최신 계획을 읽습니다.
- **조정:** 결정론적 일정입니다. 적재 지게차가 먼저, 다음은 먼저 도착하는 순, 그다음 id 순입니다. 지게차마다 출발 지연 하나를 정해, 공유하는 모든 교차로에서 앞서 배정된 지게차와 4 s 간격을 유지합니다.
- **권고:** 모든 멤버가 같은 컨텍스트로 일정을 직접 계산하므로, 코디네이터 없이 같은 답에 도달합니다. 각자 채택한 지연을 게시합니다.

```bash
python tools/swarm_demo.py      # 9개 검사 -> results/swarm.json
```

| 라운드 | 충돌: 조정 없음 → 스웜 | 총 지연: 스웜 vs 교차로에서 대응* |
|---|---|---|
| 지게차 4대 | 4 → 0 | 14.5 s vs 23.5 s |
| fk2가 구역을 떠남 | 3 → 0 | 12.0 s vs 18.0 s |
| 적재 fk5 합류(우선 통과) | 7 → 0 | 25.5 s vs 62.0 s |

\* 교차로에서 대응한다는 것은 교차로마다 선착순으로 통과한다는 뜻입니다. 늦게 온 지게차는 정지할 때까지 제동해 기다리고, 정지와 재출발에 3 s를 더 씁니다. 컨텍스트 읽기는 ≈ 6–7 ms(중앙값)입니다.

## 모델 전달 (TR-0077 7.3): [`edgeguard/model_delivery.py`](../../edgeguard/model_delivery.py)

FL 코디네이터는 전역 모델을 `EdgeGuardFL/models`에 게시합니다. 이를 구독한 각 사이트의 모델 관리자가 세 단계를 거칩니다.

1. **카나리:** 새 모델을 사이트의 보유 보행 데이터로, 현재 활성 모델(없으면 등속 모델)과 비교 평가합니다. 2 % 이상 낫지 않으면 거부합니다.
2. **활성화:** 다음 샘플부터 위험 엔진(`method: guidance_fl`)이 이 모델로 작업자를 예측합니다. 예측기는 1 s와 2 s 위치를 내고, 그 사이는 선형으로 잇습니다.
3. **감시:** 실시간 구간에서 활성 모델을 채점하고, 같은 구간에서 이전 버전을 섀도 평가합니다. 이전 버전이 3구간 연속으로 이기면 롤백합니다.

상태는 `<site>/model`(`egs:mdlDp`)에 있습니다. 버전, 이전 버전, 상태(canary / active / rejected / rolled_back), 카나리·기준·실시간 오차를 담고, 이력은 flexContainerInstance로 남습니다.

| 버전 | 부산 보유 데이터 오차 (2 s) | 결정 |
|---|---|---|
| v0 미학습 | 1.262 m vs 등속 0.577 m | 거부 |
| v1 전역 (4개 사이트) | 0.468 m | **활성화** |
| v2 손상된 업데이트 | 3.783 m | 거부(v1 유지) |
| v3 부산 특화 | 0.400 m vs v1 0.468 m | **활성화** |
| 레이아웃 변경(좁은 통로, 잦은 정지) | 실시간: v3 0.62 m vs 섀도 v1 0.47 m | **v1로 롤백** |

코디네이터 게시부터 사이트의 결정까지 ≈ 15–40 ms입니다. 이 데모는 모델을 직접 학습하고, 연합 라운드는 [`fl_demo.py`](../../tools/fl_demo.py)가 실행합니다.
