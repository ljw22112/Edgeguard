# 안전성 논증 (Safety case)

[← README](../../README.ko.md) · [English](../safety-case.md) · [강건성](robustness.md) · [현장 방식 비교](site-compare.md)

EdgeGuard가 왜 작업자와 지게차를 떨어뜨려 놓는지를 GSN(Goal Structuring Notation) 방식의 안전성 논증으로 정리했습니다. 위험원, 각 위험원의 완화책, 모든 주장의 근거를 담았습니다. 여기 있는 근거는 모두 **시뮬레이션과 소프트웨어 근거**입니다(이 프로젝트는 실기기 검증을 하지 않음). 인증이 아니라, 시범 현장이 현장 데이터로 확장할 논증입니다.

## 최상위 주장

**G0.** 작업자와 지게차가 통로를 함께 쓰는 창고에서 EdgeGuard는 둘 사이의 접촉을, 현장이 지금 쓰는 가장 엄격한 방식(6 m / 3 m UWB 근접 경보)만큼 드물게 유지하면서 지게차 생산성을 지킵니다. 일반 상황 **과** 예외 상황 모두에서입니다.

맥락: [`sim/multi_sim.py`](../../sim/multi_sim.py)의 다대다 현장(36 × 24 m, 작업자 8명, 지게차 4대, 무작위 네트워크와 UWB 오차), [`sim/robust_eval.py`](../../sim/robust_eval.py)의 시나리오, [`edgeguard/device_policy.py`](../../edgeguard/device_policy.py)의 단말 규칙과 펌웨어([`firmware/`](../../firmware)).

## 위험원

| ID | 위험원 | 흔한 원인 |
|---|---|---|
| H1 | 경로를 건너거나 경로에 서 있는 사람에게 지게차가 닿음 | 늦은 경고, 사람이 멈추지 않음, 지게차가 제때 못 멈춤 |
| H2 | 사람이 옆에서 지게차로 걸어 들어감 | WAIT 뒤 다시 걸음(무시, 시간 초과), 잘못된 방향으로 비켜섬 |
| H3 | MEC 앱이 멈추거나 재시작 | 호스트 고장, 소프트웨어 업데이트, 네트워크 분리 |
| H4 | 메시지 유실 · 지연 · 순서 뒤바뀜 | 손실이 큰 무선, 혼잡한 셀, 지터 |
| H5 | 위치가 틀림 | UWB 오차, 비가시(NLOS), 추적기 지연 |
| H6 | 아무도 따르지 않는 경보 | 오경보가 사람들에게 태그를 무시하게 만듦(근접 시스템이 꺼지는 주된 이유) |

## 주장, 논거, 근거

| 주장 | 논거(완화책) | 근거 |
|---|---|---|
| **C1** 충돌은 대응할 수 있을 만큼 일찍 예측된다 (H1) | MEC 호스트에서 충돌 경로 예측(작업자 CV / 지게차 CTRV), 학습된 선행 시간에 WARNING, 작업자가 양보(WAIT / STEP ASIDE), 지게차는 정지 범위로 제한 | [`tests/test_alert_state.py`](../../tests/test_alert_state.py), [`tests/test_multi_pair.py`](../../tests/test_multi_pair.py), 아래의 현장 비교와 대규모 평가 |
| **C2** 지게차는 경로 안의 사람 앞에서 멈춘다 (H1, H4) | **정지 지점**(이동 권한): 모듈이 매 0.1초 자기 위치로 현장 좌표에 맞춰 제동, `v_cap(d) = a(-tau + sqrt(tau^2 + 2d/a))`, a = 2.3 m/s² < 구동계 2.5, tau = 0.1초. 지연이나 갱신 유실이 제동을 늦추지 못함 | [`tests/test_stop_guarantee.py`](../../tests/test_stop_guarantee.py)(속성 기반, 실제 단말 · 구동 코드로 약 5,000 사례): 제때 받은 정지 지점은 **절대 넘지 않음**, 늦게 받으면 물리적 정지 거리 이내로만 넘음, MEC 침묵에도 유지, 펌웨어 = 파이썬([`tests/test_device_policy.py`](../../tests/test_device_policy.py)) |
| **C3** 정지 지점은 멈췄을 때 안전 반경이 지켜지는 곳에 놓인다 (H5) | 경로를 따라 사람 앞 `sqrt(r_safe^2 - lat^2) + env_margin`에 배치, 지게차 쪽으로 반올림, 위치 오차에 흔들리지 않음(가까워지기만 하고, 실제로 움직였을 때만 멀어짐) | `test_stop_point_placement_keeps_r_safe`: 경로 방향 오차가 `env_margin`(채택 정책 0.505 m) 이내면 거리 ≥ r_safe |
| **C4** 계속 걸어 들어오는 사람도 보호된다 (H2) | 걸어도 모든 지게차에 대해 안전할 때만 GO, 태그의 D2D 규칙이 가까운 지게차를 보면 MEC가 조용해도 WAIT 유지, 모든 지게차에서 떨어진 쪽으로만 · 경로를 가로지르지 않게만 STEP ASIDE, 지게차 모듈의 **상시 D2D 긴급제동**(1.5초 안 충돌 경로, 최근접 거리 1.3 m 미만), MEC · 네트워크와 무관 | [`tests/test_device_policy.py`](../../tests/test_device_policy.py)(`test_aeb_*`, 펌웨어 동일성), [`tests/test_worker_cue.py`](../../tests/test_worker_cue.py), 준수율 85 % / 70 % 시나리오 |
| **C5** MEC 앱의 침묵이나 재시작이 공백을 만들지 않는다 (H3) | 침묵: 마지막 계획 1.3초 유지 후 계획 중인 지게차는 2초 뒤 정지, 로컬 D2D 규칙은 MEC 침묵 중 **과 복귀 후 1.5초** 동안 동작(재시작한 앱은 경보 상태를 잃음), 정지 지점은 유지되는 계획의 일부, **태그 GO 확인**: 응답 없이 끝나는 WAIT나 침묵 전에 받았다가 해제되는 WAIT(재시작한 앱이 잃었을 수 있음)는 작업자의 마지막 속도로 다시 걸어도 트럭과 만나지 않을 때만 끝남(D2D), 경로 안의 사람 앞에 선 트럭은 계속 정지 | `test_silence_never_lifts_the_limit`, `test_local_fallback_only_while_mec_silent`, `test_stop_point_survives_silence`, `test_tag_go_check_sees_the_truck_he_would_walk_into`, `test_wait_is_orphaned_only_by_a_silence_after_it`, `test_firmware_tag_go_check`, MEC 재시작 시나리오 |
| **C6** 유실 · 지연 · 순서가 뒤바뀐 메시지가 결과를 바꾸지 않는다 (H4) | 계획 확인: 지게차가 적용 중인 모든 계획을 보고(위치 샘플, SDT speedLimit 모듈)하고 MEC 앱이 빠진 것을 재전송, 단말은 같은 쌍의 마지막 적용 메시지보다 오래된 메시지를 버림 | `test_plan_not_reported_by_the_forklift_is_sent_again`, `test_plan_report_through_the_twin_confirms_the_plan`, `test_late_message_is_dropped`, `test_firmware_msg_order`, 통신 불량 시나리오 |
| **C7** 경보는 따를 가치가 있게 유지된다 (H6) | 경로 근처 사람은 지게차만 조용히 제한(진동 없음), 예측된 충돌만 경보, 조우당 한 번 | 지게차 1시간당 경보와 불필요 비율([site-compare.md](site-compare.md)) |
| **C8** 정책이 시험에 맞춰 조정되지 않았다 (전체) | 시드 10,000 ~ 100,000번대로 학습, 별도 검증 시드에서 충돌 0인 후보만 선택, 둘 다에 쓰지 않은 시험 시드로 보고, 검증에서 떨어진 후보도 숨기지 않고 보고 | [robustness.md](robustness.md)(기각: 검증 충돌 4건의 미세 조정, 2건의 센서 업그레이드 정책) |

## 가정 (논증이 기대는 것)

| ID | 가정 | 쓰이는 곳 | 성립하지 않으면 |
|---|---|---|---|
| A1 | 구동계는 명령 후 0.2초 안에 2.5 m/s² 이상으로 감속 | C2 | 모듈의 `STOP_DECEL`을 낮춤(현장 파라미터) |
| A2 | 지게차 경로 방향의 작업자 위치 오차 ≤ `env_margin`(0.5 m) | C3 | 남은 충돌이 나온 곳이 측위 오차 시나리오(0.35~0.6 m), 측위 품질은 도입 요건 |
| A3 | 두 단말이 상태를 단말 간 방송(ESP-NOW / 사이드링크), 10 Hz, 약 25 m | C4, C5 | D2D가 없으면 긴급제동과 침묵 대체가 꺼지고 MEC 계획과 2초 정지가 남음 |
| A4 | WAIT를 받은 작업자는 약 0.8초 뒤 멈춤(준수율 100 / 85 / 70 % 모델) | C1, C4 | 준수율 85 %, 70 % 시나리오로 측정 |
| A5 | 시뮬레이션의 물리 · 사람 모델이 방식들의 순위를 매길 만큼 현장을 대표 | G0 | 근접 경보 대비 차이가 큼(처리량 2.0배, 좁힌 경보 대비 충돌 0 대 12). 절대 수치는 현장 데이터 필요 |

## 잔여 위험

- **측정됨:** 스트레스 시험 세트에서 채택 정책은 2,400 에피소드 중 충돌 2건(둘 다 MEC 재시작 직후), 이전 정책은 8건([robustness.md](robustness.md)). 아래 대규모 평가가 신뢰구간을 줍니다.
- **시뮬레이션이 다루지 않는 것:** 뛰는 사람, UWB에서 완전히 가려진 사람, 계획에 없는 경로로 후진하는 지게차, 운전자 시야를 가리는 적재물, 모듈 자체의 하드웨어 고장(현장에서는 모듈 자가진단과 워치독 추가).

## 관련 표준 (방향 참고, 준수 주장 아님)

- OSHA 29 CFR 1910.178(n)(8): 지게차는 안전하게 멈출 수 있는 속도로 운행해야 함. 정지 범위와 정지 지점이 이를 사람마다 명시적으로 만듦
- ISO 3691-4(무인 산업용 트럭): 사람 감지와 감속 구역. 사람 주변 자동 속도 제어에 가장 가까운 기준
- ISO 13849-1(제어 시스템의 안전 관련 부분): 긴급제동과 침묵 대체는 모듈(로컬, 네트워크와 독립)에 있어, 제품에서는 이 부분을 성능 수준(PL)에 맞춰 설계
